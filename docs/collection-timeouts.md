# 수집 제한시간과 장애 처리

## 기본 정책

`config/settings.yaml`의 `collection_timeouts`에 초 단위로 설정한다.

| 항목 | 기본값 | 범위 |
|---|---:|---|
| browser_setup | 15 | Playwright 시작·브라우저·컨텍스트·페이지 준비 전체 |
| navigation | 15 | 페이지 접속 및 기본 locator 동작 |
| price | 25 | 주가 수집 단계 전체 |
| news | 30 | 뉴스 수집 단계 전체 |
| financial | 30 | 재무 수집 단계 전체 |
| short_interest | 30 | 공매도 수집 단계 전체 |
| benchmark | 20 | 지수 하나의 수집 전체 |
| cleanup | 10 | 브라우저 정리 상한 (작업 프로세스에서는 최대 5초) |
| stock | 90 | 한 종목의 모든 수집 단계가 공유하는 예산 |
| consecutive_timeouts | 3 | 동일 소스·메서드가 연속 시간 초과되면 이번 실행에서 건너뜀 |

수집 단계 시간에는 Python 프로세스 시작·라이브러리 로드·수집·정리가 포함된다.
종목 전체 예산의 남은 시간이 단계 제한보다 짧으면 남은 시간을 사용한다.
종목 예산 때문에 단축된 단계의 시간 초과는 소스의 연속 장애 횟수에 넣지 않는다.
남은 시간이 1초 미만이면 새 프로세스를 시작하지 않는다. 자동 재시도는 없다.

각 단계는 독립 Python 프로세스에서 실행된다. yfinance의 동기 호출이 웹 서버의
이벤트 루프를 막지 않는다. 브라우저도 단계별로 만들기 때문에 한 번 고장 난 세션을
다음 종목에서 재사용하지 않는다. 시간 초과·취소·정상 완료 후 해당 작업이 소유한
하위 프로세스를 정리한다. Linux `/proc`에서 자식과 시작 시각을 확인하므로
다른 서비스의 브라우저를 종료하지 않는다. 분리된 프로세스 그룹의 Chromium도 포함한다.

단계 예산 중 최대 1초를 프로세스 종료에 예약한다. 따라서 설정한 값보다 수집에
실제로 쓸 수 있는 시간은 최대 1초 짧을 수 있다. SIGTERM 후 0.1초 대기하고,
남은 작업에는 SIGKILL을 보내며 부모 프로세스 회수도 제한시간을 둔다.
운영체제 스케줄링에 따른 작은 시간 오차는 생길 수 있다.

## 결과와 화면

- `ok`: 정상 수집, `empty`: 정상 응답이지만 데이터 없음.
- `timeout`: 시간 초과, `error`: 수집 오류, `skipped`: 연속 장애로 생략.
- `unsupported`: 소스 미지원. 현재 국내 투자자 동향·거래량이 해당한다.
- 주가가 없으면 해당 종목은 실패로 기록하고 다음 종목을 처리한다.
- 뉴스·재무·공매도만 실패하면 수집한 주가를 보존하고 부분 수집으로 기록한다.
- 뉴스가 없는 경우와 뉴스 수집이 실패한 경우는 구분한다. 가격이 정상이어도
  부가 데이터의 수집 오류는 동향 화면의 확인 필요에 포함된다.
- 단계별 상태·경과 시간·오류는 `results.json`의 종목별 `collection_status`에 저장된다.
  집계는 `collection_summary`로 저장하고 리포트와 완료 화면에 표시한다.
- 진행 화면은 현재 단계와 `경과 시간 / 제한 시간`을 보여준다. 기준지수 수집도
  진행 단계에 포함되며, 지수 수집 실패만으로 종목 리포트 생성을 중단하지 않는다.

수정된 코드와 설정은 **서버 재시작 후 시작하는 분석부터 적용**된다.
이미 실행 중인 이전 코드의 작업에 제한시간을 소급 적용할 수는 없다.

## 검증

```bash
venv/bin/python -m unittest discover -s tests -v
venv/bin/python -m tests.browser_smoke
```

테스트는 무응답 프로세스, SIGTERM을 무시하는 분리된 자식 프로세스,
분석 취소, 브라우저 준비/종료 지연, 부분 결과 보존, 다음 종목 진행,
연속 장애 차단, 빈 결과와 오류의 구분, 수집 중 API 응답과 화면의 경과 시간 표시를 확인한다.
실제 외부 소스의 데이터 품질·가용성은 별도 문제이며 제한시간 적용이 이를 보장하지는 않는다.
