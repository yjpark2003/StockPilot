# 대시보드 개선 (2026-11-01)

## 적용 단계

1. **동향 요약**: `/`에서 선택 구간의 상승·하락·보합·확인 필요 종목 수와 큰 변동 종목을 표시한다. 필터의 시장 선택에 따라 요약도 바뀐다. 종가가 두 개 미만이거나 거래일이 빠진 종목은 방향 집계에서 제외한다.
2. **종목 비교**: 마지막 종가·기준일·통화, 구간 등락률, 미니 차트, 이전 구간/지수 대비, 데이터 상태를 제공한다. 종목명/코드 검색, 시장·ETF 필터와 정렬을 지원한다.
3. **탐색 통일**: 동향 `/`, 리포트 기록 `/history`, 종목 관리 `/dashboard`. 기존 `/?y=…&m=…` 링크도 리포트 기록 화면을 연다. 저장된 HTML은 원본을 변경하지 않고 서빙할 때 공통 메뉴를 붙인다.
4. **종목 관리**: 추가·수정·삭제, 직접 입력, 중복 등록 안내를 지원한다. 국내는 6자리 코드, 해외는 티커를 검증한다. 오래된 검색 응답은 무시하고 진행 중인 검색은 시장 변경/창 닫기 때 취소한다. 로딩 실패를 종목 수 0으로 표현하지 않는다.
5. **화면 정리**: PC 비교표는 모바일에서 카드로 전환된다. 공통 헤더, 라이트/다크 모드, 키보드 조작 가능한 기본 dialog를 사용한다. 보합은 중립색으로 표시한다. 신규 리포트의 요약은 미래 전망 대신 구간 관측 사실로 표현한다.
6. **구간 비교**: 겹치지 않는 직전 저장 구간과 비교한다. 동일 거래일 수이고 두 구간 모두 해당 종목의 가격이 완전할 때만 등락률 차이(%p)를 표시한다. 새 분석에서는 KOSPI, KOSDAQ, S&P 500도 수집한다. 해당 종목의 모든 거래일에 기준지수 가격이 있어야 지수 대비를 표시한다.

## 데이터와 호환성

- 분석 결과는 `reports/weekly/<날짜>/results.json`에 종목별로 저장한다. 실패 종목도 이름과 원인을 남긴다. 기존 `meta.json`은 유지한다.
- `GET /api/overview?report_date=YYYY-MM-DD`가 저장 결과를 읽는다. 날짜를 생략하면 가장 최근 날짜 폴더를 선택한다. 페이지 조회 중 외부 시세를 수집하지 않는다.
- 이전 리포트는 HTML에 포함된 차트의 JSON 배열과 종목 정보를 읽어 복원한다. JavaScript를 실행하지 않는다. 기존 HTML에 저장되지 않았던 실패 종목의 이름·원인과 기준지수 값은 복원할 수 없다.
- 구간 등락률은 **첫 종가 대비 마지막 종가**다. 마지막 종가는 실시간 현재가가 아니다. 소스에서 조정한 종가가 포함될 수 있다. 현지 통화 기준이며 계좌 수익률이나 비중 가중 수익률이 아니다.
- ETF 분류는 저장된 상품 유형을 사용한다. `market: ETF`인 기존 국내 설정도 인식한다. 기존 해외 종목에 유형이 없으면 종목 관리에서 수정하거나 새 분석에서 수집된 유형을 사용한다.
- 지수 비교는 수집 성공한 새 분석부터 제공한다. 과거 결과와 소스 부재는 `—`로 표시한다. 새 분석은 시작/종료일을 지정했을 때 5일로 잘라내지 않고 전체 구간의 가격을 저장한다.
- 기존 개인 설정 파일과 리포트를 일괄 변경하거나 분석을 자동 실행하지 않는다.

## 확인 방법

기존 서버를 재시작한 뒤 `/`에 접속한다. 분석 실행은 `/history#analysis`에서 한다. 구간 검증 중이거나 날짜가 잘못되면 해당 구간 실행 버튼을 비활성화한다. DART 공시 포함은 같은 패널에서 선택한다.

```bash
venv/bin/python -m unittest discover -s tests -v
venv/bin/python -m tests.browser_smoke
```

브라우저 검증은 실제 앱을 ASGI로 연결하고 별도의 임시 종목 설정에서 추가·수정·삭제한다. 외부 요청을 차단하며 스크린샷은 `/tmp/stockpilot-preview/`에 저장한다. 시스템에 Chromium 실행 권한이 필요하다.
